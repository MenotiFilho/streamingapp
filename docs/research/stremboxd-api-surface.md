## 1. Is it a plain Stremio addon?

### 1.1 Three distinct live manifests

Stremboxd serves **three tiers of manifest from one addon id** (`community.stremboxd`, version `2.0.0`), generated by three different functions in `backend/src/modules/stremio/stremio.service.ts`:

| Tier | URL shape | Generator | Live-checked |
|---|---|---|---|
| 1 — global | `https://api.stremboxd.com/manifest.json` | `generateBaseManifest()` `stremio.service.ts:287-325` | 200 |
| 2 — config (no login) | `https://api.stremboxd.com/<base64url config>/manifest.json` | `generatePublicManifest()` `stremio.service.ts:330-489` | 200 |
| 3 — logged-in user | `https://api.stremboxd.com/stremio/<userId>/manifest.json` (`userId` = 32 lowercase hex) | `generateDynamicManifest()` `stremio.service.ts:532-690` | 200 for a real id; `404 {"error":"User not found"}` for a fake one |

**Tier 1, verbatim (trimmed to the structural fields, live 2026-10-15):**

```json
{
  "id": "community.stremboxd",
  "version": "2.0.0",
  "name": "Stremboxd",
  "logo": "https://api.stremboxd.com/logo.png",
  "background": "https://api.stremboxd.com/background.jpg",
  "resources": ["catalog", { "name": "meta", "types": ["movie"], "idPrefixes": ["tt"] }],
  "types": ["movie"],
  "catalogs": [
    { "type": "movie", "id": "letterboxd-popular", "name": "Popular This Week",
```

**Tier 3 (per-user) manifest adds**, and this is conditional (`stremio.service.ts:661-672`):

```js
const resources = ['catalog'];
if (exposeStreams) resources.push({ name: 'stream', types: ['movie'] });           // showRatings || showActions
resources.push({ name: 'meta', types: ['movie'], idPrefixes: ['tt'] });
if (options.nativeSync) {                                                          // supporter + opt-in
  resources.push({ name: 'player', types: ['movie'], idPrefixes: ['tt'] });
  resources.push({ name: 'library', types: ['movie'], idPrefixes: ['tt'] });
}
```

Base catalogs on tier 3 (`getBaseCatalogs()`, `stremio.service.ts:206-255`): `letterboxd-watchlist`, `letterboxd-diary`, `letterboxd-friends`, `letterboxd-liked-films`, `letterboxd-recommended` (only when `TMDB_API_KEY` is set), `letterboxd-popular`, `letterboxd-top250`, plus `letterboxd-search`; plus one `letterboxd-list-<LID>` per Letterboxd list, `letterboxd-watchlist-<username>` per external watchlist, and `letterboxd-contributor-<t>-<id>` per director/actor/studio (`stremio.service.ts:377-409, 570-583`).

### 1.2 Extra parameters (`extra`)

There is **one combined dropdown** carrying sort, genre and decade in a single param named `genre` (`stremio.service.ts:88-89`):

```js
const COMBINED_EXTRA = { name: 'genre', options: [...SORT_OPTIONS, ...GENRE_NAMES, ...DECADE_OPTIONS],
                         isRequired: false, optionsLimit: 1 };
```

- `SORT_OPTIONS` (`stremio.service.ts:73-83`): Recently Added, Oldest Added, Film Name, Release Date (Newest/Oldest), Your Rating (High/Low), Average Rating (High/Low), Popularity, Popularity (Week), Popularity (Month), Shortest, Longest, Shuffle, Not Watched, Released Only. The public variant drops `Your Rating (High/Low)` and `Not Watched` (`PUBLIC_SORT_OPTIONS`, `:84-86`).
- Sort labels map to Letterboxd API sort codes in `SORT_LABEL_TO_API` (`stremio.service.ts:53-68`), e.g. `"Recently Added" → "DateLatestFirst"`, `"Popularity (Week)" → "FilmPopularityThisWeek"`, `"Your Rating (High)" → "AuthenticatedMemberRatingHighToLow"`.
- Decades (`DECADE_OPTIONS`, `:70`): 2020s … 1920s.
- `skip` is a separate extra (`{ name: 'skip', isRequired: false }`).
- `search` is required on the search catalog only.
- Parsing of the single `genre=` value (sort vs genre vs decade) is `parseCombinedFilter()` in `backend/src/modules/stremio/catalog/catalog-filter.ts`.

### 1.3 Transport: v3 REST, not legacy JSON-RPC

Routes are plain REST resource paths (`/…/catalog/movie/<id>[/<extra>].json`, `/…/meta/movie/<imdbId>.json`, `/…/stream/movie/<imdbId>.json`, `/…/player/…`, `/…/library/…`), i.e. the HTTP transport described by the Stremio addon protocol. There is **no `/q.json?b=<base64 JSON-RPC>`** handler anywhere in the repo (`grep -rn "q.json"` → no matches). In Stremio-core terms this is `AddonHTTPTransport`, not `AddonLegacyTransport`. Both resources and `manifest.json` are served with `Access-Control-Allow-Origin: *` where the handler sets it explicitly (`stremio.routes.ts:205`, `:263`, `:324`, `:422`, …).

### 1.4 What an install URL alone buys you

Install URL shapes, from the frontend (`src/app/configure/page.tsx:1092`, `:1149-1156`) and the backend (`auth.routes.ts:174`):

```
public mode : https://api.stremboxd.com/<base64url(config)>/manifest.json
full mode   : https://api.stremboxd.com/stremio/<userId>/manifest.json
Stremio install deep link: stremio://<host><path>   (scheme swapped in, page.tsx:1153)
```

The config segment is `JSON → base64url` with **no encryption or signature** (`backend/src/lib/config-encoding.ts:32-36`; schema at `:3-28`). Field meanings: `u` username, `c` catalog toggles, `l` custom list ids, `f` contributors, `r` show ratings, `n` renames, `w` extra watchlists, `o` order, `s` sort variants, `h`/`nh` release filters, `q` search. A third-party client already documents this exact format: `Quantumishard/harbor-custom` `src/lib/stremboxd/config.ts` (`export const STREMBOXD_BASE = "https://api.stremboxd.com"`).

Live-verified behaviour, 2026-10-15:

| URL installed | watchlist | liked | diary | friends | quick actions | poster ratings |
|---|---|---|---|---|---|---|
| `…/manifest.json` (tier 1) | ✗ not declared | ✗ | ✗ | ✗ | ✗ (`stream` not declared) | n/a |
| `…/<cfg>/manifest.json` with `u` set | ✓ (public watchlist) | ✓ | ✗ not declared | ✗ | ✗ | ✓ |
| `…/stremio/<userId>/manifest.json` | ✓ | ✓ | ✓ | ✓ | ✓ (`stream`) | ✓ |

Live proof: `GET …/<cfg with u=dave>/catalog/movie/letterboxd-watchlist.json` → `200`, 100 metas; the same for `letterboxd-liked-films`. The public manifest *never* lists `letterboxd-diary` or `letterboxd-friends` (`generatePublicManifest()` only pushes popular/top250/watchlist/liked/lists/contributors/external watchlists/search — `stremio.service.ts:337-463`).

**So: no — a bare manifest URL does not give watchlist/diary/friends.** Tier 1 gives only Popular, Top 250 and a search catalog. Watchlist/liked need a config built on their site (or a hand-built base64url segment). Diary/friends/actions need `POST /auth/login` to obtain a `userId`.

### 1.5 Manifest details worth recording

- `idPrefixes`: **no top-level `idPrefixes`**; `["tt"]` appears only inside the `meta`, `player` and `library` resource descriptors (`stremio.service.ts:299-301`, `:668-671`). Catalog and stream resource entries carry no `idPrefixes` for `stream` (`{ name: 'stream', types: ['movie'] }`).
- `behaviorHints`: always `{ "configurable": true, "configurationRequired": false }` on all three tiers. `GET /configure` and `GET /:config/configure` and `GET /stremio/:userId/configure` all 302 to `https://stremboxd.com/configure` (`app.ts:142-144`, `stremio.routes.ts:310-315`, `:467-472`).
- `stremioAddonsConfig` (issuer `https://stremio-addons.net` + signature) is present on tier 1 and tier 3 but **absent on tier 2** (`stremio.service.ts:323`, `:525`, `:688` vs no such field in `generatePublicManifest`).
- `logo` and `background` are served by the API, not the site: `/logo.svg`, `/logo.png` (rasterised at startup with `sharp`), `/background.jpg` (`app.ts:28-129`).
- **Observed inconsistency:** the tier-1 manifest advertises the `letterboxd-search` catalog, but `GET https://api.stremboxd.com/catalog/movie/letterboxd-search.json` and `…/letterboxd-search/search=matrix.json` both return `404 {"message":"Route GET:… not found"}`. The search route only exists under a config segment (`…/<cfg>/catalog/movie/letterboxd-search/search=<q>.json` → 200, 5 metas for `matrix`). [inference] the tier-1 search entry is dead until Stremio appends a config, which the tier-1 URL does not have.

## 2. What the addon protocol does *not* carry

### 2.1 There is no ratings resource — ratings ride in strings

The protocol has no resource for "my rating". Stremboxd smuggles two different things into existing fields:

**(a) Poster star badges** are not a protocol feature: the server rewrites the `poster` URL to its own image proxy with the rating as a query parameter, in both catalog and meta payloads.

- `backend/src/modules/stremio/catalog.service.ts:94-97`:
  ```ts
  export function buildPosterUrl(originalPoster, rating) {
    if (!originalPoster || !rating) return originalPoster;
    return `${serverConfig.publicUrl}/poster?url=${encodeURIComponent(originalPoster)}&rating=${rating.toFixed(1)}`;
  }
  ```
  Used at `catalog.service.ts:196` (watchlist), `:246` (diary), `:292` (list entries), `:367` (friends activity), `:150-151` (adult-poster fix).
- `stremio.routes.ts:165-198` serves `GET /poster?url=&rating=` and composites a badge with `sharp` (`poster.service.ts:50-140`). Poster proxying is restricted to `letterboxd.com`, `boxd.it`, `a.ltrbxd.com`, `s.ltrbxd.com`, `images.metahub.space`, `image.tmdb.org` (`url-allowlist.ts:4-15`, `poster.service.ts:10-23`). Live check with a non-allowlisted host → `400 {"error":"Invalid poster URL"}`.
- The meta route rewrites the *Cinemeta* poster the same way when the user is logged in (`stremio.routes.ts:574-580`).

Live sample from the public watchlist catalog:

```
"poster":"https://api.stremboxd.com/poster?url=https%3A%2F%2Fa.ltrbxd.com%2Fresized%2Ffilm-poster%2F…&rating=4.0"
```
So the *community* rating is visible in a catalog meta. The *user's own* rating is not in the catalog metas for tiers 1–2; it appears in the `description` of diary entries as star glyphs (`catalog.service.ts:229-232`) and, for logged-in users, is fetched live per film (`getFilmRatingData()`, `meta.service.ts:298-349`).

**(b) Quick actions** are `stream` items whose `externalUrl` points at an HTML page on the API host, carrying an HMAC token. `backend/src/modules/stremio/meta.service.ts:409-506`:

```ts
streams.push({
  name: rating.watched ? '✓ Watched' : '○ Watch',
  description: rating.watched ? 'Click to remove from watched' : 'Click to mark as watched',
  externalUrl: `${baseUrl}/action/${userId}/watched/${letterboxdFilmId}?set=${!rating.watched}&imdb=${imdbId}&tok=${signAction(userId, letterboxdFilmId, 'watched')}`,
  behaviorHints: { notWebReady: true, bingeGroup },
});
```

Five such entries are emitted: info/rating line, star rate, watched toggle, liked toggle, watchlist toggle (`meta.service.ts:432-502`). The rating line is a formatted string: `"★★★½☆  3.8/5 (45.2K ratings)"`, `"✓ Watched · ♥ Liked · In Watchlist"`, `"Your rating: ★★★★ 4.0"` (`meta.service.ts:359-458`).

The write itself is a **side-channel HTTP GET returning HTML, not JSON**: `GET /action/:userId/:action/:filmId` (`stremio.routes.ts:630-717`) and `GET /action/:userId/rate/:filmId[/submit]` (`:723-817`). Each requires `tok` = first 16 hex chars of `HMAC-SHA256(key = JWT_SECRET, msg = "action:<userId>:<filmId>:<action>")` (`backend/src/lib/action-sign.ts:4-24`). A bogus token returns `403` with a hand-written HTML error page (`action-html.ts:31-43`), confirmed live. On success the API returns HTML with a `<meta http-equiv="refresh">` back to `stremio:///detail/movie/<imdbId>` (`action-html.ts:66-115`, `stremio.routes.ts:684`). So: **the rating value is never in the addon protocol's data plane; the protocol carries a link, and the state change happens on a browser GET outside the protocol.**

### 2.2 Auto-log to diary uses two protocol resources, and they are officially Stremio resources

`backend/src/modules/native-sync/native-sync.routes.ts:70-73`:

```ts
app.get('/stremio/:userId/player/:type/:id/:extra.json',  { config: RATE_LIMIT }, handler('player'));
app.get('/stremio/:userId/library/:type/:id/:extra.json', { config: RATE_LIMIT }, handler('library'));
```

Extras parsed in `event-parser.ts`: `player` → `action=start|pause|stop`, `currentTime`, `duration`; `library` → `action=libraryAdd|libraryRemove|watched|unwatched`, `videoId` (comma-joined). Guard rails: only `type=movie` + `/^tt\d{1,10}$/`, only a user with a stored `encrypted_refresh_token` and `preferences.nativeSync === true`; a diary job requires completion ≥ 80 % of duration (`job-rules.ts:3`, `:33-38`); at most 10 diary jobs per member per local day and no duplicate diary job for the same film within 6 h (`native-sync.routes.ts:22-24`, `:54-58`). The worker writes to Letterboxd: `client.updateFilmRelationship(filmId, { watched: true })` for `watch_flag`, and `client.createDiaryEntry({ filmId, diaryDate, rewatch })` for `diary` (`native-sync.worker.ts:79-91`). Entitlement is re-checked per job (`native-sync.worker.ts:60-64`).

Are `player`/`library` standard? Stremio's own protocol doc on the `feat/library-player-events-docs` branch says verbatim: *"Currently used resources are: `catalog`, `meta`, `stream`, `subtitles`, `player`, `library`"* and *"The `player` and `library` resources are events: instead of providing data, the addon receives the user's activity… Stremio sends each event once to every installed addon that declares the resource."* However, Stremio-core's own documentation (DeepWiki/`stremio-core` `addon_transport`) enumerates only `catalog`, `meta`, `stream`, `subtitles` as resources. So they are real protocol resources on a documented branch, with unclear status in shipping stable clients. **[inference]** they are what makes "auto-log to diary" reachable without a new protocol extension; Stremboxd's own FAQ limits it: *"Stremio Desktop and Web for now"* (`src/app/faq/data.tsx:113-115`).

### 2.3 Auto-sync does not go through the addon protocol at all

`src/lib/stremio-sync.ts:49-98` re-fetches the user's manifest and rewrites their Stremio account addon collection over Stremio's own web API:

```ts
const LINK_API = "https://link.stremio.com/api/v2";
const STREMIO_API = "https://api.strem.io/api";
…
await postEnvelope("addonCollectionGet", { authKey, update: true });   // read all addons
…  const next = addons.map((addon, i) => i === index ? { ...addon, manifest } : addon);
await postEnvelope("addonCollectionSet", { authKey, addons: next });   // write back
```

`addon.transportUrl === manifestUrl` is the match key (`stremio-sync.ts:70`). Nuvio gets the same treatment through a different account API (`src/lib/nuvio-sync.ts:1-12`: `https://api.nuvio.tv/.well-known/nuvio`, `https://nuvio.tv/link`, device code + polling, writes to profile index 1). Both are supporter-gated in the UI (`configure/page.tsx:848`: *"Auto-sync to Stremio/Nuvio requires a Stremboxd supporter subscription"*).

### 2.4 Non-standard resource names: none

`grep` over `backend/src` for declared resource names yields only `catalog`, `meta`, `stream`, `player`, `library`. No custom resource (e.g. no `rating`, `actions`, `config`), no custom top-level manifest keys, and the stream objects use only `name`, `description`, `externalUrl`, `behaviorHints{notWebReady,bingeGroup}` (`meta.service.ts:395-403`) — all documented Stremio `Stream` fields. What is non-obvious is *semantic*: tier-3 `meta` responses are Cinemeta pass-throughs with extra `links[]` entries (`stremio.routes.ts:586-611`: a Letterboxd film-page link plus up to 2 popular-review "links" in a category named `Letterboxd Popular Reviews`), and tier-2/3 config lives only in the URL path or a server-side SQLite row.

## 4. Auth model details (what a third party would need)

**Session credential.** A JWT, HS256, signed with `JWT_SECRET` via `jose` (`lib/jwt.ts:33-52`), payload `{sub: user.id, letterboxdId, username, iat, exp}`, TTL default `7d` (`JWT_TTL`) or `365d` (`ENTITLED_SESSION_TTL`) when the user is entitled and opted into `rememberMe` (`auth.service.ts:106-117`). It is accepted from **either** the `sb_session` cookie **or** `Authorization: Bearer` (`middleware/auth.middleware.ts:33-58`) — so a non-browser client that obtains a token can use Bearer. `session_epoch` invalidation applies to both (`auth.middleware.ts:47-58`).

**Cookie.** `sb_session`: `httpOnly`, `secure` when `PUBLIC_URL` is https, `SameSite=Lax`, `path=/`, **no `Domain` attribute** (`lib/session-cookie.ts:5-29`). The comment states the intent: *"a third-party site cannot make the browser attach it."*

**CORS.** Explicit allowlist from `CORS_ORIGIN`, `credentials: true`, methods `GET, POST, OPTIONS`, headers `Content-Type, Authorization` (`app.ts:59-66`). The env schema actively **rejects** `*` (`env.schema.ts:64-74`). Live evidence:

```
OPTIONS https://api.stremboxd.com/auth/login   Origin: https://evil.example
  → 204, no Access-Control-Allow-Origin, Access-Control-Allow-Credentials: true
OPTIONS https://api.stremboxd.com/auth/login   Origin: https://stremboxd.com
  → 204, Access-Control-Allow-Origin: https://stremboxd.com
```

So **browser** cross-origin use of `/auth/*`, `/billing/*`, `/v1/*` is blocked for any origin that is not in the allowlist. Separately, the catalog/meta/poster handlers set `Access-Control-Allow-Origin: *` themselves, so those are readable from any web page (they are public data).

**CSRF.** `sessionMiddleware` rejects mutating requests whose `Origin` header is present and not in the allowlist (`auth.middleware.ts:61-68`).

**Is there a documented third-party path?** No. There is:
- no API-key issuance, no OAuth server for third parties, no developer docs page (site sitemap has only `/`, `/configure`, `/faq`), no `/api` docs route;
- no user-agent or referer requirement anywhere in the code. (`grep -rni "user-agent|userAgent" backend/src` finds: the *outbound* spoofed browser UA in `html-scraper.ts:16`, `CATALOG_USER_AGENT` sent to Letterboxd (`config/index.ts:22`, `index.ts:35`), and `anonymous-id.ts:9` which hashes the caller's own UA together with the client IP and the date — that is analytics bucketing, not an access gate);
- no terms page that could describe or forbid third-party clients (§5).

**What is technically open to a third party, live-verified:**

| Capability | How | Blocked by |
|---|---|---|
| Read popular/Top 250/public watchlist/public lists/contributor catalogs + Cinemeta-passthrough meta | plain GET on the tier-1/tier-2 URLs | nothing (ACAO `*`) |
| Obtain `userId` + user JWT for a Letterboxd account | `POST /auth/login` with username/password (+`totp`). Verified live: request without body returns `400` validation JSON, i.e. the route is reachable from any HTTP client. | Letterboxd credentials; **3 req/min per IP** |
| Read/write a logged-in user's catalogs, streams and actions | `/stremio/<userId>/…`, `/action/<userId>/…?tok=…` | `userId` (32 hex) is the only gate for the read routes; the action routes also need the HMAC `tok` |
| Mint a token for an existing account **without** a password | — | the `tok`/session design gives no such path; `userId` alone cannot create a session (`/auth/session` requires the cookie/Bearer) |
| Use `/v1/resolve-film`, `/v1/film-rating` | Bearer user JWT | requires the login flow above |

**[inference]** The design is deliberately "our frontend only": the cookie is host-only and SameSite=Lax, CORS is an allowlist, and no key issuance exists. The two things a third party can do without cooperation are (a) read the public catalogs, and (b) drive the HTML action pages if it somehow learns a valid `tok` (the token is produced by `signAction()` inside stream responses, so it is handed out to whoever can read `/stremio/<userId>/stream/...`, which is gated only by the unguessable `userId`). There is no published, supported path for a third-party client, and nothing in the repo or on the site says otherwise.

## 6. Self-hosting feasibility

**Build blockers, in order of severity.**

1. **`@esp4ce/letterboxd-client` is not obtainable.** `backend/package.json:14` depends on `"@esp4ce/letterboxd-client": "^1.6.1"`; `backend/.npmrc` points `@esp4ce` at `https://npm.pkg.github.com` with `_authToken=${NPM_TOKEN}`; CI passes `NPM_TOKEN: ${{ secrets.GH_PACKAGES_TOKEN }}` (`.github/workflows/ci.yml`). `npm view` → 404 on npmjs; anonymous GitHub Packages fetch → `401 authentication token not provided`. The package has no public repo (author's public repo list, above). The author's own answer to a request to open it (issue **#7**, closed 2026-03-05) is:

   > "heyyy no i'm sorry i cant put the client public cause if letterboxd see it they will problably patch what i use... I must keep it private for myself and some stremio dev to make sure what's in it is safe x)"

   Since `backend/src/modules/letterboxd/letterboxd.client.ts` is a single line — `export * from '@esp4ce/letterboxd-client';` — every Letterboxd read and write in this codebase goes through that opaque package. **[inference]** without the author's credentials, `npm ci`/`tsc` cannot complete, so the backend cannot be built at all; a fork would have to reimplement the client first.

2. **Letterboxd API app credentials.** `CATALOG_CLIENT_ID` and `CATALOG_CLIENT_SECRET` are **required** (`env.schema.ts:14-15`, `min(1)`), and `configure({clientId, clientSecret, userAgent})` is the first thing `main()` does (`backend/src/index.ts:38-43`). These are Letterboxd API client credentials, which per the archived API page are granted only on application and explicitly not for personal/private projects.

3. **`curl` and fonts are runtime dependencies.** The HTML path shells out to `curl` with a Chrome UA because "Letterboxd/Cloudflare blocks Node's fetch (undici) on several paths via TLS fingerprinting" (`backend/src/lib/html-scraper.ts:1-35`). `backend/railpack.json` installs `fonts-dejavu-core` + `fontconfig` for the poster badge text.

**Required environment (from `backend/src/config/env.schema.ts:3-78`):** `PORT`, `PUBLIC_URL`, `ENABLE_HTTPS`/`HTTPS_CERT_PATH`/`HTTPS_KEY_PATH`, **`CATALOG_CLIENT_ID`**, **`CATALOG_CLIENT_SECRET`**, `CATALOG_USER_AGENT` (default `StremioAddon/1.0.0`), **`ENCRYPTION_KEY`** (exactly 64 hex chars = AES-256 key), **`JWT_SECRET`** (≥32 chars), `JWT_TTL` (7d), `ENTITLED_SESSION_TTL` (365d), **`DASHBOARD_PASSWORD`** (≥8), optional Polar set (`POLAR_ACCESS_TOKEN`, `POLAR_PRODUCT_ID_YEARLY`, `POLAR_PRODUCT_ID_MONTHLY`, `POLAR_PRODUCT_ID_FOUNDER`, `POLAR_FOUNDER_BENEFIT_ID`, `POLAR_SERVER`, `FRONTEND_URL`), `DATABASE_PATH` (default `./data/stremio-letterboxd.db`), backup vars (`BACKUP_ENABLED`, `BACKUP_INTERVAL_HOURS`, `BACKUP_INITIAL_DELAY_MINUTES`, `BACKUP_KEEP`, `BACKUP_DIR`, `BACKUP_S3_*`), cache vars (`CACHE_MAX_SIZE`, `CACHE_FILM_TTL`, `CACHE_WATCHLIST_TTL`), optional `TMDB_API_KEY`, optional PostHog (`POSTHOG_API_KEY`, `POSTHOG_HOST`), `CORS_ORIGIN` (default `http://localhost:3000`, `*` rejected), `LOG_LEVEL`. The config parse **exits the process** on failure (`config/index.ts:6-12`). No `.env.example` exists (it is gitignored).

**Other stack facts relevant to self-hosting:** SQLite via `better-sqlite3` with 8 SQL migrations (`backend/src/db/migrations/001…008`); `sharp` for logos and poster badges; `jose` for JWTs; Polar (polar.sh) for billing, optional — unset means billing routes return 503 and entitlement resolves false (`config/index.ts:41-45`); PostHog analytics optional. Deployment configs are Railway-specific (Railpack, `/app/data` volume, healthcheck `/health`) in `backend/railway.toml`; `backend/nixpacks.toml` also exists. Frontend needs `NEXT_PUBLIC_BACKEND_URL` (defaults in code: `http://localhost:3001` in `configure/page.tsx:32`, but `https://api.stremboxd.com` in `src/lib/billing.ts:4` — an inconsistency [inference: a `NEXT_PUBLIC_BACKEND_URL`-less build would hit production from some paths]).

**What works without a Letterboxd account:** tier-1 catalogs (Popular, Top 250) and tier-2 catalogs driven only by `username`, including public watchlist and liked films (both live-verified with `u=dave`, 100 metas/page) — these use the app token via `callWithAppToken` (`public-catalog-fetcher.service.ts:23`, `:57-67`). **What breaks without a Letterboxd account:** diary, friends activity, quick actions, recommendations (needs `TMDB_API_KEY` and a logged-in session), and auto-log — every one of these needs a stored encrypted refresh token (`user-client.service.ts:29-95`; `catalog-fetcher.service.ts:102-159`). Even the public watchlist breaks if that member's watchlist is not public (FAQ: *"It must be set to Public in your Letterboxd privacy settings"*, `faq/data.tsx:54`).

**Verdict (factual, not a recommendation):** as published, the repo cannot produce a working backend without (a) the private npm package, (b) Letterboxd API app credentials, and (c) at least one Letterboxd account for the full-mode features. The MIT license does not convey any of those.

## 7. The Letterboxd side

**Does Letterboxd offer a public/official API today?** It offers an official API that is **not publicly self-serve**: `https://api.letterboxd.com/api/v0/`, documented at `https://api-docs.letterboxd.com/` (both behind Cloudflare for direct fetches — I read the archived capture, 2026-07-28, and the archived `https://letterboxd.com/api-beta/` page, 2025-12-31). Quotes from the API docs ("Overview" and "Authentication" sections of the archived spec):

> *"Each endpoint URL takes the form of `https://api.letterboxd.com/api/v0/ENDPOINT_PATH`…"*
> *"…there is an enforced limit of 100,000 objects returned in the paginated data, to discourage API consumers from copying our complete dataset. Parameters and endpoints marked as 'First Party' are only available to Letterboxd's own apps, due to licensing restrictions."*
> *"The Letterboxd API uses standard OAuth2 Password, Client Credentials, Authorization Code and Refresh Token authorization flows… **The Password flow is for first-party use only.** Third-party API consumers must use the Client Credentials or Authorization Code flows."*

And the application-gated access page: *"Access to the Letterboxd API is available by request only… we are not granting access for… private or personal projects…"* (verbatim text in §5).

**What Stremboxd actually uses.**

- **Official API for everything programmatic.** `backend/src/modules/letterboxd/letterboxd.client.ts` re-exports `@esp4ce/letterboxd-client`, which exports `BASE_URL` (imported as `API` by the test suite: `backend/tests/helpers/msw-server.ts:3`), `configure`, `authenticateAsApp`, `authenticateWithPassword`, `createAuthenticatedClient`, `refreshAccessToken`, `getCurrentUser`, `LetterboxdApiError`, `TwoFactorRequiredError`, `GENRE_NAMES`, and typed methods. The test suite mocks the following paths under that `BASE_URL` (`msw-server.ts:68-201`), i.e. the endpoints the client calls: `POST /auth/token`, `GET /me`, `GET /films`, `GET /film/:id`, `GET /film/:id/me`, `GET /film/:id/statistics`, `PATCH /film/:id/me`, `GET /member/:id/watchlist`, `GET /member/:id/lists`, `GET /list/:id/entries`, `GET /list/:id`, `GET /log-entries`, `GET /activity`, `GET /search`, `GET /member/:id`, `GET /lists`, `GET /contributors`, `GET /contributor/:id/contributions`, `GET /film/:id/reviews`. These all exist in the official spec (archived endpoint index, §3 of the capture).
- **App token (client credentials) for public data:** `getAppToken()` → `authenticateAsApp()` with the `CATALOG_*` credentials, cached until 60 s before expiry, refreshed on 401 (`lib/app-client.ts:10-37`). Used for public watchlists, member lookup, list resolution, contributors, dashboard enrichment (`public-catalog-fetcher.service.ts:57-67`, `auth.routes.ts:266-292`, `stremio.routes.ts:112-128`).
- **Password grant + TOTP for user login:** `authenticateWithPassword(username, password, totp)` (`auth.service.ts:51-61`), with `2FA_REQUIRED` surfaced to the UI (`auth.routes.ts:110-117`; `configure/page.tsx:759-786`). **This is the flow the docs mark first-party-only.** [inference] Stremboxd operates as a first-party-styled client against a private API that officially excludes its use case.
- **Refresh-token rotation:** `refreshAccessToken(refreshToken)` on every user-client creation; `invalid_grant` → `SessionExpiredError` (`user-client.service.ts:39-55`). Tokens are stored encrypted (below).
- **Reads:** watchlist, liked films, diary (`getMemberLogEntries`), friends activity (`getFriendsActivity`), list entries, film search, film statistics, reviews (`catalog-fetcher.service.ts:66-195`, `meta.service.ts:157-201`, `:530-586`).
- **Writes:** `updateFilmRelationship(filmId, {watched|liked|inWatchlist|rating})` → the spec's `PATCH /film/{id}/me` (`stremio.routes.ts:669-674`, `:804`; `native-sync.worker.ts:81`) and `createDiaryEntry({filmId, diaryDate, rewatch})` → the spec's `POST /log-entries` (`native-sync.worker.ts:89`).

**HTML scraping (not the API) for identifier discovery.** `backend/src/lib/html-scraper.ts` fetches `https://letterboxd.com/<username>/` and list pages with `curl` + a Chrome 131 UA to extract `boxd.it` shortlink ids, `data-list-identifier`, `data-list-boxdit-url`, `data-likeable-identifier` (`html-scraper.ts:4-95`). Comment at `:7-8`: *"Letterboxd/Cloudflare blocks Node's fetch (undici) on several paths via TLS fingerprinting, so we shell out to curl which uses a different TLS stack."* The docs' own recommended LID discovery is `HEAD` on the page and read `x-letterboxd-identifier`, or take the `boxd.it` path — Stremboxd uses the HTML shortlink route for members and lists (`auth.routes.ts:38-54`, `:336-437`).

**[inference]** So the answer to "does it scrape?" is: it scrapes *identifiers* from HTML with a UA-spoofed `curl`, and uses the official (application-gated, first-party password flow) API for all data and all writes. There is no third party-legal path in what the code does.
